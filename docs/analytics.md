# Метрики прототипа

Счётчик Яндекс Метрики: `113253171`. Сбор работает только в production-сборке. Просмотры экранов передаются через `hit`; дополнительное отслеживание хеша в настройках счётчика включать не нужно.

В настройках счётчика создайте цели типа **JavaScript-событие** с идентификаторами:

| Название | Идентификатор |
| --- | --- |
| Открытие карточки ученика | `student_card_open` |
| Открытие информации ученика | `student_info_open` |
| Начало оформления заморозки | `freeze_form_open` |
| Заморозка оформлена | `freeze_created` |
| Начало создания задачи | `task_form_open` |
| Задача создана | `task_created` |
| Использование поиска | `student_search_used` |
| Использование фильтра | `student_filter_used` |

Начало формы считается при её открытии, завершение — после успешного оформления. События завершения передают `elapsed_seconds`: время от открытия формы до завершения. У заморозки также передаётся `attempts`: число отправок формы, обработанных приложением. Ошибки встроенной браузерной валидации в этот счётчик не входят.

Поиск учитывается один раз за открытие страницы после паузы во вводе 700 мс; сам запрос не передаётся. Фильтры передают только категорию `filter`, без выбранных данных ученика. Имена учеников не включаются в адреса просмотров карточек. Вводимые комментарии и сообщения скрыты от записи Вебвизора.

Карта кликов, Вебвизор и отслеживание ссылок включены при инициализации счётчика. Доступ к отчётам зависит от прав аккаунта в Метрике.

Для кейса проведите два задания: найти ученика и оформить заморозку; создать задачу в календаре. Отдельно зафиксируйте число участников и самостоятельность выполнения. Цели дают начало/завершение форм, а не доказательство успешного выполнения всего задания. После задания можно устно спросить, насколько легко было выполнить его по шкале 1–7; опрос в интерфейс не добавлен.

Проценты завершения по посетителям и время работы с формой интерпретируйте вместе с наблюдениями. Переходы между страницами отражают глубину просмотра; возвращения в другие дни — удержание. Тестовые посещения разработчика следует исключить при подготовке итогов кейса.
